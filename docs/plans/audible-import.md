# Implementation Task: Audible Import for Books

Repository: https://github.com/chris-shaw-2011/books

> Implementation status and current decisions: [`audible-import-handoff.md`](./audible-import-handoff.md). The original requirements below are retained for acceptance traceability; later owner decisions recorded in the handoff supersede conflicting requirements.

## Execution instructions

Implement this feature completely, including the frontend, backend, Docker build changes, automated tests, and documentation.

**This is an implementation task, not a research or planning task.**

Work autonomously and complete as much of the implementation and verification as possible without requesting intermediate approval.

Do not stop after producing a design, proof of concept, feasibility analysis, or initial implementation milestone.

Investigate unfamiliar dependencies as necessary, make reasonable engineering decisions, and continue implementing.

If an approach proves unsuitable, select another reasonable approach that satisfies the requirements.

Do not introduce unnecessary architectural complexity or unrelated refactoring.

Follow the project's existing TypeScript, React, Fastify, shared-model, formatting, and linting conventions.

The final deliverable should be code that builds successfully, passes relevant automated tests, and can be deployed using the existing Docker publishing process.

Do not modify production deployments or use real Amazon credentials without authorization.

## 1. Navigation

Add a new **Import Audible Books** item immediately below **Upload Books** in the existing navigation dropdown.

The option must be available to all authenticated users.

Create a new import interface following the existing styling and component conventions.

## 2. Audible authentication

Use Libation CLI for Audible authentication, scanning, and downloading.

Use `node-pty` to manage Libation's interactive `login-external` process.

The user interface must:

1. Request the Audible account identifier and marketplace, defaulting to the US.
2. Start a temporary Libation authentication session.
3. Capture the Amazon login URL generated by Libation.
4. Display a **Sign in with Amazon** link.
5. When clicked, display a JavaScript alert reminding the user to copy the complete address-bar URL after authentication, even if Amazon shows an error page.
6. Open the generated URL in a new browser tab/window.
7. Display a textbox for pasting the resulting Amazon redirect URL.
8. Submit that URL to the same running Libation authentication process.
9. Automatically begin importing after successful authentication.

Handle invalid URLs, abandoned sessions, and authentication failures.

Never request or capture the user's Amazon password.

## 3. Temporary authentication

Libation authentication must be temporary.

Use isolated per-import configuration directories and sessions.

Do not persist authentication tokens, refresh tokens, or other reusable Audible credentials once importing finishes.

Do not implement scheduled synchronization or automatic future downloads.

When someone wants additional Audible books later, they must run the import process and authenticate again.

Clean up authentication files after success, failure, cancellation, or server restart.

Ensure sensitive authentication values cannot leak into application logs, SSE messages, error responses, or terminal history.

## 4. Audible library discovery

After authentication:

1. Execute Libation's `scan` operation.
2. Export the discovered library as JSON.
3. Parse its metadata into appropriate TypeScript models.
4. Compare the discovered books against the existing Books library.
5. Automatically download missing titles.

Include both purchased audiobooks and Audible Plus books.

Podcasts and podcast episodes can be excluded.

Use Libation's targeted ASIN download functionality rather than downloading the entire library indiscriminately.

## 5. Duplicate detection

**Use Audible ASIN matching exclusively.**

Do not implement title comparison, fuzzy matching, author comparison, or duration comparison.

Store imported ASINs in a way that allows Books to identify them in subsequent imports.

Prefer embedded audio metadata if technically suitable; otherwise, use a minimal persistent database mapping.

Ensure that renaming, moving, or deleting an audiobook does not leave behind incorrect duplicate detection information.

Before downloading an Audible title, check whether an existing local audiobook has that ASIN.

Skip confirmed matches.

If an existing audiobook lacks ASIN metadata, it must not be considered a duplicate.

It is acceptable for the user to receive duplicates of manually uploaded audiobooks.

Do not overwrite existing files.

## 6. Highest audio quality

Configure Libation to download the highest-quality audio available for each title.

Start with these Libation settings, verifying their behavior against the pinned version:

- `FileDownloadQuality=High`
- `UseWidevine=true`
- `Request_xHE_AAC=true`
- `DecryptToLossy=false`
- `SplitFilesByChapter=false`
- `ImportPlusTitles=true`

Prefer the highest-quality available source format.

Preserve the source audio without unnecessary lossy transcoding.

Use a compatible high-quality fallback when a preferred audio format cannot be downloaded.

Produce a single M4B file with chapters and cover art when supported.

Use FFprobe or equivalent tooling to verify the produced audio format during integration testing.

## 7. Download and import processing

Download audiobooks to a temporary staging directory.

Never expose partially downloaded files to the existing Books filesystem watcher.

After each audiobook finishes downloading and converting:

1. Validate that the resulting M4B is complete and readable.
2. Preserve the original audio, chapters, and metadata.
3. Associate its ASIN with the imported audiobook.
4. Move the M4B into the application's configured `db.settings.uploadLocation`.
5. Reuse the existing upload finalization and library indexing behavior.
6. Retrieve the resulting Books `Book` object.
7. Notify the frontend that the book is available.

The backend should reuse or extract existing common upload logic where practical.

Do not run completed M4B files through the existing AAX converter unnecessarily.

Handle cross-filesystem moves and filename collisions safely.

Each successfully imported book should become available in the Books library immediately, without waiting for the entire Audible import to finish.

## 8. Post-upload and post-import UI permissions

Fix both the existing manual upload workflow and the new Audible import workflow.

### Administrators

When an administrator completes a manual upload or when an Audible import finishes downloading a book, display the existing book editing interface.

Reuse:

`BookLink` with `editOnly={true}`

The administrator should be able to modify all currently supported metadata and move the book to another folder.

Preserve existing save and cancel behavior.

### Non-administrators

After a manual upload or an Audible import completes, display the book information without metadata editing controls. The user's account-level reading status control remains available.

Non-administrators must not be presented with editable fields, save buttons, or controls for changing the book's destination folder.

Use the existing `BookLink` component if appropriate, or extract a shared presentation component if necessary.

The user should still be able to see that the audiobook was imported successfully and dismiss the completed-book display.

### Backend authorization

Preserve the existing administrative authorization requirements for modifying book metadata.

Do not weaken `/updateBook` or other administrative endpoints to make this feature work.

Do not rely solely on frontend controls for enforcing edit permissions.

Test that non-admin users cannot modify book metadata through direct API requests.

### Editing queue

When multiple books finish importing:

- Place completed books into a queue for post-import display.
- Show the first completed book immediately.
- Continue downloading other audiobooks in the background.
- When the user finishes viewing/editing a book, show the next completed book.
- Do not block downloads while the user is interacting with the completed-book display.
- Show the number of completed books awaiting review.

Closing and reopening the import interface should not discard the queue during an active session.

## 9. Progress reporting

Use Server-Sent Events to stream import progress.

Provide a useful progress interface containing:

- Current operation.
- Current audiobook title.
- Download percentage when available.
- Total discovered books.
- Books skipped because of existing ASINs.
- Books downloaded successfully.
- Failed downloads.
- Number of remaining books.
- Number of books awaiting post-import review.
- Scrollable activity log.

Translate Libation terminal output into structured events where possible.

Do not stream sensitive authentication information.

Closing the import modal or refreshing the browser must not cancel the ongoing backend import.

Reopening the interface should reconnect to the active operation and recover its current progress.

Support user-initiated cancellation, including terminating Libation processes and removing incomplete temporary files.

## 10. Backend implementation

Create a maintainable service responsible for:

- Libation process execution.
- Interactive PTY authentication.
- Import session lifecycle.
- Library scanning and JSON parsing.
- ASIN duplicate detection.
- Targeted audiobook downloading.
- M4B publishing.
- SSE progress reporting.
- Post-import book availability.
- Temporary file and credential cleanup.

Use the existing Fastify authentication and shared TypeScript model conventions.

Isolate simultaneous sessions and prevent conflicting downloads.

Choose reasonable concurrency limits to avoid unnecessary Audible throttling. Sequential downloading is acceptable initially.

Individual audiobook failures should be reported and should not prevent remaining books from importing.

## 11. Docker and publishing

Update the existing application Dockerfiles and release workflow so the published Books image includes:

- A pinned compatible Libation CLI version.
- Its required .NET and native dependencies.
- `node-pty` and its required native dependencies.
- Other runtime dependencies needed for the selected high-quality audio formats.

Preserve the existing non-root execution model.

Do not require a separate always-running Libation container.

Do not introduce scheduled Libation background jobs.

Ensure the container can access the configured upload directory and temporary staging storage.

The rest of Books must continue to operate normally if Libation is unavailable.

Perform a production Docker build and verify that Libation and PTY dependencies load and execute correctly.

Run the project's existing relevant tests, linting, and TypeScript build checks.

Fix failures introduced by the implementation.
